Orion: Technical Architecture & System Specification

System Documentation · Version 2.0 · Ordered by Importance
Architecture Specification Summary: Orion is an air-gap-ready, zero-egress private AI intelligence platform. This document outlines the microservices topology, dense vector RAG engine, multi-agent review pipeline, and cryptographic isolation guarantees.

Orion is a self-hosted, private intelligence platform and autonomous agentic workbench designed for confidential industrial, technical, and regulatory operations. Built as a sovereign enterprise-hardened intelligence platform, Orion provides complete multi-turn Retrieval-Augmented Generation (RAG), multi-perspective specialist AI evaluations, and document comprehension without permitting confidential data to leave the local hardware perimeter.

2.3 Specialist AI Multi-Perspective Review Pipeline

Orion incorporates a 4-perspective review engine (server/endpoints/review.js) evaluating confidential proposals, designs, and incident logs:

  1. Technical Specialist Pass: Evaluates engineering specifications, tolerances, and mechanical parameters.
  2. Policy & SOP Specialist Pass: Audits compliance against internal operating procedures and safety regulations.
  3. Risk Assessment Specialist Pass: Identifies failure modes, hazard severity ratings, and operational vulnerabilities.
  4. Conflict Detector & Synthesizer: Identifies contradictions between specialist findings and synthesizes a binding final decision.

3. Application & Reasoning Server Tier (`server/`)

The server maintains workspace boundaries, orchestrates RAG pipelines, and dispatches background worker threads.

3.1 Multi-Provider LLM & Embedding Orchestrator

  • Local Model Execution: Native integrations with Ollama, LM Studio, LocalAI, and NVIDIA NIM provide 100% offline inference on local GPUs/CPUs.
  • Native Embedding Engine: Driven by @xenova/transformers executing all-MiniLM-L6-v2 via local ONNX runtime without network access.
  • LanceDB Vector Storage: Operates directly on disk using SIMD-accelerated k-NN search and columnar Apache Arrow tables.

3.2 AIbitat Multi-Agent System & MCP Skills

Autonomous workflows use the AIbitat framework coupled with the open Model Context Protocol (MCP) standard:

  • create-files/: Generates formatted .docx, .xlsx, .pptx, and .pdf deliverable documents.
  • sql-agent/: Executes parameterized read-only queries against relational databases.
  • rechart.js: Synthesizes dynamic visualization charts rendered directly in chat.
  • memory.js: Extracts and persists long-term facts across conversation sessions.

3.3 Asynchronous Worker Threads (Bree)

Long-running workloads are offloaded to Node.js worker threads using Bree:

  • embedding-worker.js: Manages asynchronous batch document chunking and vector insertions.
  • extract-memories.js: Distills key facts from completed chats into the workspace memory store.
  • run-scheduled-job.js: Executes cron-based scheduled agent tasks.

3.4 Adaptive Task-Based Model Routing Engine

Orion implements an isolated, policy-driven model routing layer positioned between incoming task intent parsing and agentic inference execution. Rather than dispatching all industrial tasks to a single monolithic model, the router enforces the core sovereign allocation formula:

Task + Sensitivity + Capability + Hardware + Permission → Best Model

The decision lifecycle executes through five deterministic gates before allocating GPU compute:

  1. Intent & Modality Analysis: Classifies prompt intent (summarization, vision extraction, code generation, multi-hop reasoning, spreadsheet synthesis).
  2. Data Sensitivity Verification: Cross-references attached document metadata against workspace classification (Public, Internal, Confidential, Restricted).
  3. Hardware & VRAM Boundary Check: Probes local GPU memory via Ollama / vLLM API to confirm sufficient available VRAM for the target model's quantization profile (e.g. Q4_K_M vs FP16).
  4. Permission & Clearance Verification: Validates user RBAC role and session authorization for the requested model tier.
  5. Dispatch & Fallback Binding: Binds the cleared model to the AIbitat agent session; gracefully degrades to a smaller local fallback if GPU memory is saturated.

4. Collector Ingestion Microservice (`collector/`)

The Collector (port 8888) handles the extraction and tokenization of unstructured documents, isolating compute-intensive tasks away from the main API.

4.1 Document Parsers & Token Budgeting

Format Parser Engine Conversion Strategy
PDF Documents pdf-parse Extracts native text streams, page boundaries, and structural metadata.
Word Documents mammoth Translates .docx semantic markup into clean plain text.
Spreadsheets xlsx / csv-parse Extracts multi-sheet tables, cell relationships, and headers.
Presentations pptx Extracts slide text sequences and speaker notes.

4.2 OCR & Audio Transcription

  • Tesseract.js OCR: Automatically invoked when documents lack native text layers (scanned engineering drawings, blueprints). Image frames are pre-processed with contrast normalization before character recognition.
  • Whisper Audio Transcription: Media files (MP3, MP4, WAV) are normalized via FFmpeg to 16 kHz mono WAV and transcribed with timestamped segments.

6. Security, Isolation & Zero-Egress Architecture

Orion is built for high-compliance environments where data cannot cross network perimeters:

6.1 Air-Gap Isolation Model

  • Zero Outbound Networking: When configured with local LLMs (Ollama/LM Studio), native ONNX embeddings, and LanceDB, all operations run on localhost with zero external network calls.
  • Zero Telemetry: System metrics and setup surveys complete locally without transmitting diagnostic data to external servers.
  • Hardware Vitals Telemetry: Polls local host hardware vitals (CPU load, free RAM) via Node.js native os module.

6.2 Cryptographic Key Management & IPC Security

  • Signed Inter-Process Communication (IPC): Server-to-Collector requests are verified using RSA-SHA256 signatures (SIG_KEY and SIG_SALT) with timestamp expiration checks.
  • Data-at-Rest Encryption: Sensitive provider keys and credentials stored in SQLite are encrypted using AES-256-CBC / AES-256-GCM via EncryptionManager.
  • Authentication: JWT session tokens with bcryptjs salted password hashes.

6.3 Industrial Threat Mitigation Matrix

Orion is specifically hardened against failure modes unique to autonomous agentic systems operating over confidential industrial datasets:

Threat Vector Industrial Impact Scenario Orion Architectural Countermeasure
Indirect Prompt Injection Adversarial instructions concealed inside vendor PDFs, engineering drawings, or scraped web pages instructing the agent to exfiltrate private tokens or execute malicious shell commands. Strict parser sanitization in isolated Collector; deny-by-default execution privileges; code execution confined to ephemeral sandboxes; state-altering tool calls require human authorization.
Context Data Contamination Classified blueprints or confidential telemetry unintentionally leaked to unauthorized workspace users during multi-turn RAG retrieval. Document sensitivity tags inherited across context tokens; workspace-level cryptographic isolation; LanceDB vector queries scoped strictly to active user RBAC filters.
Hallucinated Technical Metrics Model hallucinates equipment calibration numbers, pressure thresholds, or formulas, leading to hazardous real-world operations. Mathematical computations offloaded to deterministic sandboxed Python scripts; Specialist Review pipeline enforces citation grounding against raw source pages.
Silent Network Telemetry Third-party libraries, model runners, or dependencies transmit background telemetry beacons or crash diagnostics to external cloud endpoints. Zero outbound networking enforced at host OS socket level; elimination of all telemetry endpoints; signed RSA-SHA256 IPC used exclusively between internal microservices.

6.4 Ephemeral Tool Sandbox Isolation & MCP Protocol

Tools capable of executing arbitrary code or querying production systems operate inside decoupled boundaries:

  • Model Context Protocol (MCP) Standard: All external skills adhere to the open standard, formalizing JSON-RPC tool schemas, input validations, and error boundaries.
  • Isolated Container Execution: Python execution tools run in ephemeral, restricted containers without network access, with restricted CPU/memory quotas, and read-only filesystem mounts.
  • Human-in-the-Loop Sign-Off: Actions categorized as high-impact (database mutations, file deletions, email dispatch) trigger an explicit interactive confirmation modal before execution proceeds.

6.5 Demonstrable Sovereign Verification Protocol

Sovereignty is verified through empirical testing across seven operational criteria rather than subjective claims:

# Verification Criterion Expected Operational Behavior Empirical Verification Method
1 Zero External Egress No network traffic crosses external gateway during ingestion, RAG chat, or agentic tool runs. Monitor network interfaces with netstat -ano or Wireshark; confirm zero non-localhost connections.
2 Data Classification Integrity Ingested files inherit sensitivity tags stored immutably in SQLite metadata. Inspect workspace_documents table for metadata.classification assignments.
3 Context-Aware Model Allocation Router allocates coding tasks to code models, diagrams to multimodal, and logic to reasoning models. Review Server API execution logs to confirm model dispatch matching prompt modality.
4 Tool Permission Gate Unauthorized tool requests trigger immediate block events without executing on the host. Trigger an un-cleared tool action; verify 403 Forbidden event in audit trail.
5 Multi-Step Error Recovery Intermediate tool exceptions or missing context trigger local repair cycles rather than workflow failure. Simulate tool syntax error; verify AIbitat agent autonomous retry in execution logs.
6 Citation & Deliverable Grounding Generated Word and Excel deliverables include explicit page/section source references. Inspect generated .docx or .xlsx deliverables for source footnote traceability.
7 Cryptographic Audit Logging Every actor, touched file, model checkpoint, and tool call is captured in structured JSONL/SQLite logs. Verify audit logs under server/storage/logs/ for chronological cryptographic event records.
